# 取得ペースの基準(調整で「徐々に」を作る)

隠したりロックしたりせず、**コストと素材の分布の調整**だけで「周回を重ねるたびに少しずつ取れる」を作る。
数字を変える時はこの基準に照らし、`acqrate2.js` / `acqrate_early.js`(scratchpad)で実測すること。

## 基準(スキルのLvアップ数 / 1周回≒5分)

| 段階 | 想定状態 | 目標 | 実測(5分換算) |
|------|----------|------|----------------|
| 序盤 | 素の状態・ボルトのみ | 2〜4件 | 2〜5件 |
| 中盤 | 軍勢あり+採集強化 | 8〜14件 | 10件 |
| 深化 | Lv3以上 | 新ティア素材が必須(海・遠隔大陸へ行かないと不可能) | 貪欲シムでもLv2止まりを確認 |

## ペースを作っている仕組み(全て「調整」であり、表示は隠さない)

1. **量の伸び**: 魔物素材はレベルごとに約1.6倍(`matCost`)。オブジェクト専用素材は緩やか
2. **種類の節目**: Lv3/5/7/9で新しい種類の素材が必要。高レベルほど高ティア=遠い土地(`matCost` steps)
3. **心得の基本量1.5倍**: 心得は数が多く、安いと中盤に一気に取り切れるため基本素材のみ1.5倍
   (序盤の主力=靴・カリスマ・シールド等には影響しない)
4. **武器はコイン経済**: 価格の等比列(40×1.6^Lv)と、狩り続けるほど相場が下がる仕組みで自然に段階化
5. **新天地は物語**: 場所はクエスト報酬のヒントと実際の到達でのみ分かる(危険度の高低で行き先を選ぶ)

## 測定方法

- `acqrate_early.js`: 素の状態で実キー入力3分 → 拾えた素材で貪欲にスキルを取り、件数を数える
- `acqrate2.js`: 中盤相当(骸骨の軍勢10・採集3)で同様
- 判定はばらつきがあるため、外れた場合は2〜3回実行して傾向を見る

## パワーアップ(コイン経済)の基準

| 段階 | 目標(レベル/周回) | 実測 |
|------|--------------------|------|
| 序盤〜中盤 | 3〜5 | 専用財布の貪欲購入で6前後/周回 → 武器・納品と財布を分け合う実際は4〜5 |

- 調整: `gcost` の基本価格を一律1.5倍(調整前は1周回目に10レベル買えた)。伸び率(×1.4/Lv)は据え置き
- 測定: `coinpace.js`(実測収入モデル 240/周回+15%成長で10周回の貪欲購入)

## 武器の基準

- 新しい武器は**2〜3周回に1本**(専用財布の試算で毎周回1本 → 財布共有の実際は半分のペース)
- 価格の等比列(×1.6/Lv)は据え置き。上位武器は前提武器のレベルでさらに段階化

## 新天地(基地・港)の基準

- 場所を知る手段は物語のみ(ヒント・実際の到達)。おおよその到達目安:
  最初の基地=1〜2周回目 / 2〜3個目=3〜5周回目 / 最初の港の修理(木材15+鉄クズ8+🪙150)=4〜6周回目 /
  海を渡って別大陸=6周回目以降
- 素材・コイン収入(上の実測)がそのままゲートになるため、専用の調整項は持たない

## 周回時間・距離・進行の基準

| 軸 | 基準 | 実測(回避しない自動プレイ=悲観値) |
|----|------|--------------------------------------|
| 周回時間(素の状態) | 2〜5分で力尽きる(死に戻りで強化して再挑戦、が前提のループ) | ボット下限90秒。開始大陸の全敵はプレイヤー(速度42)より遅い(最速32)ため、人は歩いて振り切れる |
| 周回時間(中盤投資) | 8〜15分 | 調整前5.6分 → 調整後7.6分(回避しないボットの悲観値。実プレイは上振れ) |
| 距離 | 素の速度42px/sで最初の基地(8.5km)まで約3.4分 → 1〜3周回目に到達。速度・HPを1〜2個買えば安定 | 敵速度の検証により徒歩で振り切り可能(交戦し続けるボットのみ失敗) |
| 進行(基地/クエスト) | 北の砦=1〜3周回 / 東の遺跡=2〜4周回 / 分岐3方向=3〜5周回 / 港修理=4〜6周回 / 別大陸=6周回〜 | 要求量÷実測収入の算術(questpace.js)と一致 |

## 節目の難易度(数を一息、個体を一段)

一辺倒に数だけ増やさない。**敵の種類が増える節目(3/7/12/20/30分)ごとに、
数はいったん少し引いて(×0.87 → 2.5分かけて元の伸びへ)、個体が一段強くなる**
(色違い・大型の割合が節目ごとに+0.5段ぶん跳ね上がる ― 見た目で分かる強化のみ。隠しステ倍率はなし)。

**基準**: 総威力(数×平均の個体強さ)は節目の直後も下がらない。実測(phasecheck.js):
- 節目7分: 数×0.89 / 個体×1.35 / 総威力×1.21
- 節目12分: 数×0.90 / 個体×1.95 / 総威力×1.74
- 節目20分: 数×0.89 / 個体×1.42 / 総威力×1.28
- 節目3分は基礎数(192)が支配的で数の引きは僅か(個体強化×1.16のみ体感)

色違い・大型は仲間になっても強さを保つため、節目の強化は敵味方で対称(魂の共鳴の設定と矛盾しない)。

## 基地パワーアップの実効性(新設ではなく、元からの項目を意味あるものに)

- **実効性監査(upaudit.js)**: 全g_*を単独Lv5にして周回開始し、ステータス差分かコード参照が
  あるかを毎回検査。死んでいた「潮流の型」「潮の息継ぎ」(存在しないキー指定)を修理
- **名前の意味に効果を合わせる**: 湯治の癒し=HP回復+0.8/秒 / 薬師の膏薬=回復+0.5/秒 /
  行軍の号令=自分と仲間の脚+1% / 遠見の術=射程+回収範囲 / 荷駄の護衛術=攻撃+脚 /
  詩人の囁き=勧誘率を倍に
- 既存で既に旅に効くもの: 星図の導き(脚+22.5%) / 風の運び手(脚+20%) / 白亜の商才(コイン) /
  癒しの水(泉+15/秒) / 骸骨の軍勢(出撃時の仲間) など ― 新項目は足していない

## 序盤の圧の漸増(2分かけて通常へ)

一気に全圧をかけない。いずれも「開始からの時間」による調整で、隠す要素はない:
- 環境の敵密度と補充速度: 開始時60%→2分で100%(初期配置も60%)
- 群れ: 初回は45〜75秒後から。開始2分は頭数も6割
- 大群(横スクロールの波): 初回150〜210秒。総数の伸びを緩め、早くから複数波に分割
- 世界イベント(大移動など): 3周回目から現れる

## 海路(船)のペース

**基準**: 船の素の速度は初期徒歩と同じ42。海路の所要は陸路と同尺(初期地点→北の砦=8.5km/約3.4分が物差し):
隣接大陸 1〜2分 / その先の連鎖 +1〜2分。速さは (1) 帆の研究+8%/Lv・造船学+5%/Lv(調整で徐々に)、
(2) 航路の早瀬(港と大陸を結ぶ海の道。乗ると通常×5.5相当・凪×6.5相当)で得る。

**世界の車輪配置**(v2。大陸を拡大しつつ海は狭いまま。形の文法=弧・三日月・くびれ・半島は維持):
- 面積比の基準: 他大陸は初期大陸の**最大5倍まで**。実測: 竜骨4.5 / 黄昏3.2 / 星嵐2.8 / 深緑2.8 /
  最果て2.2 / 太陽1.8 / 虚無1.8(初期大陸=1、無変更)
- 配置は車輪状: 四大陸を東/南/西/北の等間隔に(本土との海峡6000〜6600)、対角の継ぎ目(NE/SE/SW/NW)に
  島の飛び石(霧NE・燃えさしSE・風待ちSW・夕凪群島+環礁+霜NW)。遠環(太陽・虚無・最果て)はその外側
- 対角の空洞は新しい陸を作らず、**既存の大陸の形(半島)で埋める**: 星嵐の腰から東へ長い腕+
  北の肩から北西へもう一本の腕 / 竜骨の背に北のこぶ+頭から南東へ尾びれ / 黄昏は北西へ長く弧を
  描いて虚無の門の入り江を囲む岬+南西の岬。霜の小島は1.5倍の「霜の島」に。
  拡大後の面積比: 竜骨4.99 / 黄昏4.48 / 星嵐4.22 / 深緑2.79(上限5倍を維持)
- 終端の大陸も孤立させない: 太陽の大陸は竜骨の背の真上×星嵐の腕の右の角に(下・左の2方向) /
  虚無は黄昏の胴の左×弧の岬の下(右・上) / 最果ては星嵐の北×北西の腕の右(下・左)
- **方向の基準(確定)**: 左右上下のうち「岸から30000px以内に、目に見える陸(実効半径8000以上)」の
  ある方向を数える。**3方向以上何もない大陸=ゼロ / 2方向何もない大陸=4つまで**
  → 実測: 2方向何もないのは太陽・虚無・最果ての3つのみ。本土と四大陸は3〜4方向。
  半島の地続き連結も含めdircov.jsで毎回検証(岸から行進する実測ギャップで判定)
- どの大陸・基地からも複数方向に隣の陸がある(一方通行の鎖をやめた)。方角を語る台詞は
  実座標との突き合わせ監査済み(diraudit: 26件全て一致)
- 基地の配分も初期大陸に寄せない: 拡大した大陸の内陸に基地を追加(竜の湯=竜骨5 /
  白風の宿場=星嵐7 / 苔の庵=深緑5)。配分は 本土4 / 竜骨4 / 黄昏4 / 星嵐3 / 深緑3 / 島・遠環8。
  いずれも既存NPCの物語(湯汲み・荷継ぎ・薬売り)からヒントが出る
- 大陸内の基地は一直線に並べない: 中盤の基地を半島・岬へ横に散らしてジグザグの三角配置に
  (竜の湯=南東の尾びれ / 白亜の灯台=北のこぶ / 黒曜の祠=南西の岬 / 月影の社=北西の岬 /
  白風の宿場=東の腕 / 苔の庵=東の岬)。方角を語る台詞は移設に合わせて再監査済み
- 衝突は数値ソルバー+癒着チェック(中心間の連続海4500px)で解消。landmass22・基地の所属・
  海の幅3000以上・危険度勾配(1歩≦+2)を検証済み

**実測**(素の船・強化なし・早瀬に乗って直行、着岸まで):
- 東の港→竜骨48秒 / 南の港→深緑31秒 / 北の港→星嵐37秒 / 西の港→黄昏22秒 /
  南西の港→黒曜103秒 / 北東の港→霧の小島19秒(岩礁経由)
- 早瀬上の実速: 185〜248。着岸後は大陸内の陸路(2〜4.7万px)が探索の本体になる(大陸が大きくなったぶん)

**遠隔の港(遠環の大陸への玄関口)**: 四大陸より先の大陸へは、近くの大陸の港街から渡る。
- 白亜の港(竜骨・灯台の麓)→ 霧の小島・太陽 / 嵐の港(星嵐・塔の東の浜)→ 最果て・太陽 /
  月影の港(黄昏・岬の南岸)→ 虚無。修理費は本土の港より高い(🪙2500〜3500+素材)
- 場所は物語で知る: 観測手ミオ(白亜の港街とまとめて)/ 塔守デン(太陽の見当と一緒に)/
  月の使者ツクヨ(施設解放の礼)。船大工は3人とも専用の声。修理後は転送ゲートの出撃先にもなる

## 深海圏(何もない沖の壁)

**目的**: コンテンツの無い外洋へ延々と進ませない。ただし初見殺しにも、テキスト説明にもしない。

**基準**:
- どの陸の岸からも**12000px**(実測の壁開始は岸から約9400px≧8000)を越えた沖から、
  1100pxごとに危険度+1(上限+10)。壁の入り口は+1あたり800〜1000px=船で十数秒の猶予
- **航路の早瀬とその周辺(6000px以内)では発動しない**。全16航路・本土→隣接大陸の全海峡で
  発動ゼロを毎回検証(voidwall.js)
- 伝え方はテキスト無しの3つ: 海と空気が距離に応じて暗く沈む(画面グラデーション)/
  地図・ミニマップでも深海の海色が暗い / HUDの危険度数字と現れる魔物の強さ

## バイオドーム(と海域・敵・素材)の導入勾配

- セルのバイオームは「穏やか→過酷」の並びの先頭から、始まりからの距離で使える種類が増える:
  **開始大陸(〜13km)=4種 → 13〜26km=8種 → 26km以降=全16種**(実測)
- 海域・敵の顔ぶれ・素材はバイオームに連動しているため、同じ勾配で自動的に段階化される
- セルの形・境界・条件(ボロノイ+ドメインワープ)は不変

## 「毎周回、どれかが新しい」の担保

全要素が常に新しくなる必要はない。周回ごとに下のどれかが必ず動く:
- スキルの新規取得(2〜5件/周回) / パワーアップの新レベル(4〜5/周回、コインは必ず貯まる)
- 新しいバイオドーム・海域(移動距離が伸びれば自動)
- 物語の一歩(ヒント・基地・港・施設解放クエスト) / 新しい武器(2〜3周回に1本)
- 3周回目からは世界イベントが周回ごとの変化を足す

## マップの実景と地形の障害

- **基地マップの実景(HUB_THEME)**: ストーリーに出てくるものは画面内に実物として置く ―
  泉(南の泉)/ 御神木(深緑)/ 大炉(西の炉・鍛冶神)/ 湯壺と湯気(竜の湯)/ 歌碑(黄昏)/
  回る灯台(白亜)/ 骨のアーチ(竜骨)/ 観測器(霧・星)/ 墓石とかがり火(墓標・骨)/
  月(月影)/ 日輪の鏡(太陽)/ 氷晶(霜)/ 環礁の潟(沈み都)/ 避雷針の塔(嵐)/ 薬草園(苔の庵)など25基地全て。
  空気の演出(霧・蛍・火の粉・星・雷光)もテーマごと。街の作り直し後は、
  建物と壁が矩形の地形として当たり判定を持ち、テーマの実物は飾りとして重ならない位置にだけ出る
- **周回マップの岩場**: 壊せない露岩の群れを決定論(チャンクのハッシュ、約6%のチャンクに1〜3個)で
  ところどころに自然配置。基地・港・道・出発点のそばには出ない。主人公・仲間・敵とも縁に沿って
  回り込む(ボスは押し通る)。岩の中には湧かない(canStand)
- 検証: hubtheme.js(壁が止める・戸口から入れる・石段で高さが上がる・主が壁に埋まらない) /
  townshot.js(全28マップの到達性) / cragtest.js(2000個の生成規則・押し出し・湧き) /
  fuzz.js(新規〜終盤・全時間帯・全UI状態の総当たりでエラー/NaN/異常値なし、終盤大所帯3.2ms/frame)

## 絵作りの言語(デザイン全面統一。システム・数値は不変更)

- **統一ライティング**: 全スプライト(主人公・敵・ボス・NPC・建物・オブジェクト)に
  「上からの淡い光+足元の落ち影」を生成時に一度だけ焼き込む(sprites.js shadePass)。
  全ての絵が同じ光の中にいる質感になる。per-frameコストゼロ
- **地面の質感**: 市松模様を廃止し、決定論ノイズ(tileHash)のまだらに。周回マップの
  草地・砂地・海、拠点の床とも同じ手法。人工的な格子が消え土地らしくなる
- **光もののエフェクトは加算合成**(lighter): 火花・波紋・雷・レーザーなど戦闘の
  フィードバックが発光する。攻撃予兆(メテオの着弾円・ブレスの扇)は視認性優先で通常合成のまま
- **ビネット**: 周回・拠点とも画面周縁をわずかに落とす(キャッシュ済み1drawImage/フレーム)
- **UIは「暗いガラスのピル」**: HUD・お知らせリボン(情報は静か/危険だけ赤く脈動)・
  キーキャップ[E]・ミニマップ枠・拠点の上部バー/施設マップ・マップ内の名札チップ
  (基地名・港名・行商人・貿易商・待機中・護衛中・標)まで同一言語
- **タイトル**: 背景は魂の広場を実際の街の絵として描く(下の「タイトル画面」の節)
- 制約: 戦闘関連システム(数値・当たり判定・挙動・バランス)は一切変更しない。
  攻撃予兆の視認性を落とす変更もしない

## 街と広場のマップ(全ハブの実景)

- **魂の広場**: 先人オウが築いた祭壇(手記二頁目・オウの告白の実物)を奥の正面に、
  石柱の環+魂のかがり火が囲む。施設は環状配置(研究所・宿舎が中段、書庫・武器庫が両翼)、
  魂の泉(通れない地形の障害)が西に、住民は東側に住む。施設の建物は全て専用の造形 ―
  祭壇(石壇+魂の炎)/研究所(丸屋根+蒸留器)/宿舎(天幕)/書庫(本の塔)/武器庫(交差剣)/石碑(刻まれた立石)
- **港町**: 港ごとに家並み・網干し場・樽・灯柱の配置が違う(portScenery、決定論)。
  家と樽は通れない(円の押し出し)。桟橋・実寸の船・灯柱の暖色の灯りは共通の骨格
- **基地**: HUB_THEME のテーマ実景(泉・大炉・湯壺・灯台など25基地全て)+
  家並みは基地ごとに軒数3〜5・位置・大きさが違う(決定論)。特別強化施設も専用の造形 ―
  武練場(的と交差槍)/生命の祠(苔むした小祠)/秘宝の蔵(白壁の蔵)
- 新要素の噂話: 見晴らし台・古の祠・先人の遺物・色違いの宝箱は村人の噂話(NPC_TIPS)にも
  織り込み、画面で見たものに物語の側から意味が繋がる
- **街の地形**: 踏み固められた土の道がゲートから中央広場を経て各施設へ通い、

  必ず開く仕組みなので、どの配置でも詰まない(terraceOf: 上段の施設のxから階段を導出)。

  なので回り込み・湧き規則がそのまま効く)

## 腐る効果を残さない基準(実測監査)

- **基準**: パワーアップ・スキル・スキルの各強化段階に「ゲーム全体で一度も役に立たない
  効果」を残さない。データ定義を読むだけでは分からないため、**実際にゲームを動かして測る**
- 測り方(deadfx.js): 解放系のパワーアップは「何も買っていない状態」を基準に、
  効果量・ステータス系は「解放系だけ買った状態」を基準にして、1件ずつ最大Lvにして比較。
  スキルは前提スキルを満たしたうえで上限まで取得(Lv6から効く効果まで測るため)。
  効果量(powMap)は applyMods 内で設定されるため1フレーム進めてから読む
- 判定軸: ステータス差分 / 素材の解放 / スキルの解放 / 効果量の増幅 / スキル上限 /
  出撃時の仲間 / 開始時の所持素材 / 保管庫の周回跨ぎ
- **監査自体の自己検証(selftest.js)**: 存在しないステータスを指す項目と効果ゼロの項目を
  わざと注入し、どちらも「死」と判定できること・本物を誤検出しないことを毎回確かめる
- **飽和の検証(satur.js)**: 全パワーアップ+全スキルを最大にした状態から1件だけ外し、
  「買っても1ミリも変わらない」項目が無いことを確認する
- **飽和の誤判定を避ける**: スキルを全て最大にした基準だけで測ると、上限に張り付いて
  「実際は効くのに差が出ない」項目(鬨の声・魂の絆など)を死と誤判定する。差が出なければ
  スキルを取らない基準でも測り直す
- 実測結果(174パワーアップ / 41スキル / 全強化段階): 死んだ効果 **0件**、
  誰も読まない効果フィールド 0件、効果値が変わらない強化段階 0件、飽和 0件

## 効果はゼロでないのに腐る、を無くす基準

効果値がゼロでなくても、**買われないまま終わる**なら結果は同じ ― その効果はゲーム中で
一度も働かない。上の監査(deadfx.js)は「効くかどうか」しか見ないので、ここでは
**値段と効き目の釣り合い**を2つの基準で測る(useful.js)。

### 収入の実測(income.js)

早送り(`Run.update` を直接回す)で1周回に稼げるコインを測る。

| 段階 | 実測 |
|------|------|
| 序盤(強化なし) | 6分で力尽きる。コインはほぼ拾えない |
| 中盤 | 6分で力尽きる |
| 終盤(全項目最大) | 20分で **50万7千** |

以降、**終盤の1周回の稼ぎ=50万** を物差しに使う。

### 基準1: どのレベルも買える

- **最終Lvの価格 ≤ 終盤の1周回の稼ぎ × 10(=500万)**
- 破っていたもの(修正前の実測): 終焉超越 最終Lv **9.3億**(総額26億)、太陽の恩寵 1.3億、
  太陽の憤怒 1.3億、終焉の器 9700万、彼方の遺物 9000万、神鉄の装備 3900万、
  虚無の帳 2000万、虚無の刃 1800万、太陽の生命 1600万、終焉狩り 665万 ― **10件**
- 原因は伸び率(×1.5〜1.55/Lv)と最大Lv(15〜25)の掛け算。×1.55を20Lv重ねると
  最終Lvは初期Lvの4000倍になり、どんな収入でも追いつかない
- 修正: `data.js` の META 定義のあとで**価格の天井**を通す。天井を超える項目だけ
  伸び率を下げて最終Lvを500万に収める。**初期Lvの価格は動かさない**ので、
  序盤〜中盤の「4〜5レベル/周回」(coinpace.js で再測定: 1周回目7・以降6→5)は変わらない
- 修正後の最大は終焉超越の総額3190万(終盤64周回ぶん)。最果ての最後の一品として妥当な底

### 基準2: 危険な土地ほど効き目が上

同じ能力を上げる項目が土地ごとにある。**危険な土地の品が、安全な土地の品より弱い**なら、
値段は高いのに効き目は下 ― 誰も買わず、その効果は一度も働かない。

- 破っていたもの(修正前): 太陽の生命(危険度10)の自動回復が癒しの水(危険度1)と同じ、
  灯火の狙撃(6)の射程が遠見の術(1)より下、骨の棘(7)の反撃が茨の鎧(0)より下、
  潮の息継ぎ(8)・薬師の膏薬(5)の回復が最低値、コイン獲得は7つの土地が横並び ― ほか多数
- 修正: 効果量を危険度順に並べ直した(価格ではなく効果を上げる。安い品を弱くしない)
- 2つ以上の能力を同時に上げる品(荷駄の護衛術・遠見の術・行軍の号令)は「広く浅く」なので
  この比較から外す
- 例外的に残る重なり: 被ダメージ軽減は上限75%、鉄の皮膚だけで60%に届く。
  各地の盾はそこに着くまでの道中では効いているため「一度も働かない」には当たらない

### 基準3: 取る頃に役に立つ

「いつか買えれば良い」では足りない。**その土地に着いた最初の周回で、そこの強化を1つは買える**こと。
実績で解放される強化も、**解放された頃の1周回の稼ぎ**で1Lv買えること。

- 収入モデル: 1周回目240コイン・以降+15%(`coinpace.js`と同じ)。到達周回 = 2 + 危険度×3
- 測定(stagefit.js): その頃のビルドを貪欲購入で組み、そこから3周回ぶんの稼ぎで
  買える枚数だけ足して、ステータスが何%動くかを見る
- 修正前の実測: 深緑の社は最安の1Lvが**3.7周回ぶん**、最果ては**4.6周回ぶん**。
  着いても何も買えず、その土地の強化は素通りされていた。実績解放も 地図学5.4 / 保存術4.3 /
  悟り4.4 / 開拓魂5.3 周回ぶんで、もらった時に使えなかった
- 修正: 危険度に沿って基本価格を引き直した(基地13カ所・実績解放16件)。
  伸び率と価格の天井は据え置きなので、上限まで買う総額はほぼ変わらない
- 結果: 「取る頃に1Lvも買えない」20件 → **3件**。残る3件(不死鳥の羽・スキル上限解放・
  終焉の書)は、安い選択肢が同じ施設に並んでいる中の高級品なので、そのまま置く
- ステータスに出ない効果(スキルの効果量倍率・出撃時の仲間・開始素材・上限解放)18件は
  この測り方では見えないため、deadfx.js の別基準で確認する

### 検査(useful.js)

`js/data.js` を直接読み、上の3基準を機械的に検査する。**現在: 全基準とも合格(0件)**

- **基準**: 他のスキルが前提のスキルも、前提の要らないスキルと**同じ場所・同じ形**で一覧に並べる。
  前提スキルは必要素材と同じ「必要なもの」の一項目として、アイコン+「名前 Lv(所持/必要)」で
  表示し、足りなければ素材と同じく赤で示す(隠して存在を分からなくしない)
- 取得できる条件も素材と同じ扱い ― 前提が揃うまでは取得ボタンが押せないだけ
- 検証: reqview.js(前提つき6スキルが全て一覧に出る/前提が必要なものとして表示される/
  未達では取得できない/前提を満たすと取得できる)

## 建物が地形そのものになる基準(街の作り直し)

置いた絵(シンボル)ではなく、**床・壁・戸口でできた地形**として建物を作る。
壁は通れず、戸口からは中に入れて、施設の主は建物の中にいる。実装は `js/town.js`。

### 部品

- **建物** = 中心・大きさ・戸口の向き。壁は厚み16pxの矩形4本で、戸口の側だけ幅78pxの穴が開く。
  中の主が立つ位置(slot)は戸口の反対側の奥に自動で決まる ― 中に入らないと話せない
- **段** = 高さを持つ矩形。人も建物も `段×22px` 持ち上がって描かれ、南の縁には崖肌が落ちる
- **石段** = 段と段をつなぐ矩形。踏んだ位置に応じて高さが**滑らかに補間**されるので、
  上りきるまで少しずつせり上がる(「ちゃんと上がっている」挙動)。石段以外で段は跨げない
- **塀・水・桟橋・焚き火跡**も同じ矩形の地形。当たり判定は矩形の押し出し(浅い辺へ逃がす=壁沿いに滑る)

### 街ごとに一辺倒にしない

### 検査(townshot.js ― 回帰スイートに常設)

全28マップで**格子の幅優先探索**を回し、壁・水・段差の規則のまま
「施設・NPC・ゲートの全てに歩いて届くか」を確かめる。届かなければ落ちる。
最初の実行で3つの街(雪の隠れ里・神殿都市・最果ての城)の通路が
人の幅より狭いことが分かり、地形を直した。
`hubtheme.js` は「壁が止める / 戸口から入れる / 石段で高さが段々上がる /
施設の主が壁に埋まっていない」を全マップで確かめる。

### 建物は、その施設の建物に見える

外から見ても中に入っても「何の建物か」が分かること。3つで決める:

- **屋根の色**(用途ごとに固有): 祭壇=紫 / 研究所=青緑 / 宿舎=土 / 書庫=菫 / 武器庫=赤錆 /
  武練場=朱 / 生命の祠=緑 / 秘宝の蔵=黄土 / 船大工=木 / 宿=橙 / 天守=藍 / 神殿=金 / 祠=青緑
- **戸口の上の看板**: ✦祭壇 ⚗研究所 ⌂宿舎 ▤書庫 ⚔武器庫 ◎武練場 ❖生命の祠 ▣秘宝の蔵
  ⚓船大工 ♨宿 ▦倉庫 ⚒工房 ☀神殿 ⛩祠
- **中の造作**: 部屋に入ると用途の道具が置いてある。研究所=蒸留器・棚・木箱 /
  書庫=本棚2つと文机 / 武練場=武器架・木人・的 / 生命の祠=小祠・水盤・薬草 /
  秘宝の蔵=長持・木箱・樽 / 武器庫=武器架・金床 / 宿=囲炉裏と卓 / 船大工=材木・綱・作業台 …

**置き場所は画面の向き基準の定位置**(奥の壁ぎわ・左右の壁ぎわ・手前の隅)。
主の立ち位置と帳場にかかる場所は空けるので、**戸口がどの向きでも主が造作に隠れない**。
造作は部屋の矩形でクリップするので、壁や屋根の上にはみ出さない。

検査(hubtheme.js に追加): 用途が付いているか / 造作が部屋からはみ出さないか /
主と帳場を埋めないか / 置き場所が足りず造作ゼロの部屋が無いか / 同じ街に見た目が同じ施設が無いか。

  施設マップ → **街の見取り図**(住人の語彙に合わせる)
- **同じ名前で口調が違う人**: 港の船大工11人が全員「船大工」表示だった。
  一人ずつ名前を付けた(タル/ナギ/フブキ/キリ/ユウ/セイ/アラシ/ハヤテ/シラホ/ライガ/ツキ)
- **意味を推し量れない説明**: 「効果量 +4%」→「スキル「◯◯」の効き目 +4%」(10件) /
  「出現を3%緩和」→「出にくくなる(-3%)」 / 「炎上を付与」→「敵を炎上させる」
- **地形の外へ押し出される魔物**: 吹き飛ばし(knockback)だけが地形を見ておらず、
  岸辺の陸の魔物が海へ飛ばされていた。押し合い(separateUnits)も同様に地形を見るようにした。
  `deep.js` が時々「LAND ENEMY SPAWNED AT SEA」で落ちていたのはこれが原因で、
  実測で再現・修正後は2回連続で0件

### 推測は推測として言う

物語の登場人物が、自分に確かめようのないことを言い切らないようにした。
`storycheck.js` に見張りを常設(言い切る語には、必ず含みを持たせる語が要る):

- ガルド「死に戻りの仕組み」→ 「そう聞いておる。ワシは見たままを言うだけじゃがな」
- リナ「絶対に何かあるわ」→ 「何かあると思うのよね。三度も見たんだもの」 /
  「あなたには先人がいるのよ」→ 「断定はできないけど…先にここへ来たんじゃないかしら」
- ザリ「どれも同じ日に死んどる」→ 「同じ日に死んだような傷み方をしとる。……ワシの目が確かならな」
- オウ「還る者は決まって門を通らずに戻る」→ 「余もお前も…二人だけの話では、法則とも呼べぬがな」 /
  「誰かがそう決めておる」→ 「誰かが決めた刻限のように、余には思えた。確かめる術も無いままじゃ」
- 修道女ルナ「力を求めすぎた魂は色が変わる」→ 「――と、修道院では教えます」

### 言葉の意味が取れるか

- **「門」**: 虚無の隠者の「全ての魂は門を通る」は、直前に灯した「ゲート」とも、
  地名の「虚無の門」とも取れて意味が定まらなかった。
  「死んだ魂は皆この門をくぐり、二度と戻らぬ。この庵が『虚無の門』と呼ばれるのは、そのためだ」に書き直し、
  手記八頁目の引用も合わせた
- **「環の世」**: 語り部リュウと村人の噂話が先に説明しているので、賢者の台詞で初出にならない(確認済み)
- **「御神火」**: 火の子エンの依頼で一度だけ「御神火 ― おばあちゃんの火」と言い添える
- **やり残しの用事**: 太陽の神官サナが「学者どのに伝えて」と頼むのに、リナ側に受け取る台詞が無かった。
  持ち帰るとリナの第一声が変わり(`afterIf`)、答えを喜んだうえで次の問いを立てる

## ストーリーを進める動機と、その場で完結しない問い(メイン側)

謎(先が気になる)と動機(進む理由)は別物なので、別々に用意する。

### 動機

- **冒頭で個人的な目的を渡す**: 地図の切れ端の裏に、自分のものではない字で
  「君も還る側なら、果ての城で待っている」。名前も来た道も思い出せない主人公にとって、

- **一頁目の手記でその字と繋がる**: 見晴らしの岩で拾う先人の手記が、裏書きと同じ字。

- **ゲートを灯す意味をそのつど言葉にする**: 解放時に「灯ったゲートは◯つめ。
  人が眠れる場所が、この世にまた一つ増えた」。人里はゲートの光の下にしか残っていない
- **サイドは世界が動くのが報い**: 依頼を果たすと誰かが移り住む(appearStory)。

## 色違い・大きさの姿(体そのものを変える)

色を塗る/拡大するだけだと「同じ魔物」に見え、格の違いが伝わらない。
かといって角・王冠・炎・光輪のような**付け足した物**を載せるのは、体に飾りを
貼っただけで、その魔物が変わったことにはならない。変えるのは体の側だけにする
(戦闘の数値は不変)。

- 基準: **輪郭と肌だけで格を語る**。体の外側に物を足さない。変えてよいのは
  (1)体つき(縦横の比率) (2)体の表面の質 (3)輪郭の硬さ の3つで、どれも体の内側に収まる
- **色違い**: 1金=縦に締まり輪郭が厚い(装甲のような肌) / 2紅=横に膨れ、体を赤熱の亀裂が走る /
  3紫=細く伸び、下半身が影に溶ける / 4青白=体が結晶の面に割れる
- **大きさ**: 1大=横に張って背が低い(下半分が重く沈む) / 2巨=さらに平たく、岩のような粗い肌
- 基準: 表面は `source-atop` で描く ― 体の形の内側にしか乗らないので、どの魔物の
  輪郭でも顔や手足を覆わず、貼り付けた物にも見えない
- 生成は組み合わせごとに一度だけ(キャッシュ、900種で一掃)。実測: 初回12.2ms / 以後4.5ms

### 仲間の色(敵だった時の色を残す)

- 基準: 仲間は**敵だった時の色の上に、全員へ同じ量の緑を一枚重ねる**だけにする。
  色相を置き換える描き方(`globalCompositeOperation='color'`)だと全員が同じ緑になり、
  「どの魔物を仲間にしたのか」が消える。重ねる方式なら、赤い魔物は赤みの残る緑、
  青い魔物は青みの残る緑になり、元が何だったか分かる(`source-atop` / #3fb950 / 34%)
- 段階の体つき・大きさ・色違いの体色も、敵だった時のまま引き継ぐ
- ただし元から緑の魔物(スライム等)は重ね色だけでは敵と見分けにくいので、
  **足元の影だけ緑を帯びさせる**(体には何も足さない)
- 実測: 仲間90+敵182の混戦で1コマ11.2ms(仲間0・敵202の素の状態が3.4ms)。
  増分は「描く体の数」ぶんで、重ね色そのものの費用はキャッシュにより無い
- 検証: bodyshot.js(5種×素/金/紅/紫/青白/大/巨/仲間3種の見本と生成時間)/
  melee.js(大所帯の混戦の見え方と1コマの時間)

## 実プレイの点検(遊んで初めて分かる不自然)

画面ごとの見た目を個別に直しても、通しで遊ぶと「そこだけ浮いている」ものが残る。
ずるをせずに鍵盤で動かし、机上の画面と触れる画面の両方で通す(playtest.js / surfaces.js)。

- **一つの押しに一つの意味**: Space が「突撃の号令」と「調べる」の両方に割り当たっていて、
  桟橋や人の前で押した一回が号令と会話を同時に起こしていた。調べるは E だけにする。
  画面を開いている間に押した Space は捨てる(閉じた瞬間に覚えのない号令が飛ばないように)
- **端末に合わせて案内を書く**: 「タップで全体図」「タップ / E で進む」のように、
  片方の端末にしか通じない書き方をしない。`Input.padOn()` で
  「N キーで全体図」「E キーで進む」に出し分ける
- **移動パネルは触れる端末にだけ**: 既定を `auto` にし、`ontouchstart`/`maxTouchPoints` が
  ある端末では最初から出す。鍵盤しかない机上の画面には、使わない輪と釦を置かない
- **画面の高さは中身に合わせる**: `.panel` を固定 600px にしていたため、数行しかない
  結果画面や転送ゲートの下に意味のない空白が広く残っていた。`height:auto` +
  `max-height` にし、中の一覧だけを `flex:1 1 auto; min-height:0` で伸ばす
  (逆に潰されてはいけない行 ― 所持スキルの帯 ― には `flex:none` を明示)
- **開いている画面の下に案内を残さない**: 街では `Hub.update` が止まるので足元の
  [E] のピルがそのまま残る。画面を開く側(`pauseFor`/スキル/一時停止)で消し、
  周回中は `updateHud` が「開いている画面があるか」を見て引っ込める
- **いま押したい釦を一番目立たせる**: 一時停止の並びで設定の切替(移動パネル)が
  「再開」より上で一番目立つ青だった。再開を先頭に出し、設定は控えめな色にする
- **軍勢の数を画面に出す**: 仲間を増やして戦うのが芯なのに、いま何体連れているかが
  どこにも出ていなかった。HUDに ⚑ の玉を足す(結果画面・ステータスとは別に、戦いの最中に要る)
- **単位の違うものを同じ書き方にしない**: ステータスの「コイン/ドロップ」は倍率と確率を
  並べていたため、初期値60%のドロップ率が「-40%」と出て、覚えのない罰に見えていた。
  「コイン倍率 +0%」と「素材ドロップ率 60%」に分ける。速度・範囲には単位(px)を添える
- **何の一覧かを必ず書く**: 技の画面の一番下に離れて出る所持一覧が「まだスキルなし」とだけ
  出ていた。「この周回で取ったスキル:」を頭に添える
- 検証: playtest.js(逃げながら実際に歩く / 張り付いて動かない敵・置いていかれる仲間・
  はみ出す文字・画面外の表示を拾う / 死に戻り / 広場の案内)、surfaces.js(施設を全部開いて
  切れ・空欄・壊れた表示を拾う)、firstrun.js(素の状態での生存時間)

### 陸の魔物が海にはみ出していた本当の原因

deep.js の「LAND ENEMY SPAWNED AT SEA」が時々だけ出ていた。吹き飛ばし・押し出しの
地形判定を直した後も残っていたので、最後まで追った。原因は**判定そのものの解像度**:

- `isLandCached` は海岸線の距離計算(全大陸×パーツを走る `coastGap`)が重いため、
  40pxの格子ごとに答えを一つ覚えていた。ところが40pxの格子ひとつに海岸線が通ることがあり、
  その格子は代表点の答え(陸)を格子全体に適用してしまう。結果、格子の海側にいる
  陸の魔物が「陸にいる」と見なされ、波打ち際からじわじわ海へはみ出していた
- 直し方: 代表点の**海岸までの符号つき距離**を見て、格子の対角(≒57px)より近い格子は
  「海岸をまたぐ」と印を付け、その格子だけは毎回きちんと測る。沖と内陸は今まで通り
  格子で済むので、負荷は増えない(終盤336体+仲間98体で5.9ms/frame)
- 併せて、**場所を指定した湧きにも環境の確認を入れた**。指定座標は素通りだったため、
  色違いの「仲間を呼んで果てる」が渚で発動すると陸の魔物が海に湧いていた
  (指名討伐の印が岩場に重なる場合も同じ)。立てない時は近くの16点を試し、
  どこもだめなら湧かせない
- 検証: summonsea.js(渚で「呼んで果てる」を20回起こして、海に出た一体ごとに
  「湧いた時点で海」か「陸から海へ動いた」かを記録)+ deep.js 4連続で0件

### 一時停止をどこでも開ける(行き止まりを作らない)

- 「あそびかた」がタイトル画面にしかなく、一度旅に出ると操作の一覧を二度と読めなかった。
  街(魂の広場・基地・港)でも P / Esc / ⏸ で一時停止を開けるようにし、

## 敵のデザインの軸(シルエットで戦い方が分かる)

色違い・大きさの段階を体つきで語るようにしても、**元の魔物そのものがみな同じ骨格**では
遠目に区別がつかない。影絵にして並べると、46種のうち20種以上が「丸い頭を持つ縦長の塊」で、
ダークナイトに至っては painter に `case 'armor'` が無く**ただの灰色の円**(泥団子)だった。

軸を「体の飾り」から**「戦い方を表す骨格」**に変える。同じ骨格を共有するのは同じ戦い方の
魔物だけにする:

| 骨格 | 戦い方 | シルエットの決まり | 例 |
|------|--------|--------------------|-----|
| brute | 近づいて潰す | 肩が張った台形。頭が肩に沈み、腕が膝まで垂れる | オーク・オーガ・イエティ・フロストジャイアント |
| undead | よろめく・脆い | 縦に細く肩が落ちる。胴に隙間が空いて向こうが透ける | スケルトン・マミー |
| caster | 遠くから撃つ・癒す | 細身に広がる裾。得物が体の外へ長く突き出る | ゴブリン弓兵・シャーマン・ネクロマンサー・セイレーン |
| armor | 硬い | 角ばった鎧。兜のスリット、張り出した肩当て、長剣 | ダークナイト |
| saurian | 前傾・尾を振る | 首が前に出て、後ろへ太い尾 | リザードマン |
| golem | 動かぬ壁 | 台形の胴に、地面近くまで届く極太の腕 | ストーンゴーレム・マグマタイタン・虚無の巨像 |

- 基準: **影絵にして並べ、同じ輪郭が二つ以上並ばないこと**(allmobs.js solid で目視)。
  painter に case の無い kind を残さない(自動検査で0件を確認)
- 傘・触手・積み重なりのように「輪郭に出る特徴」は線ではなく面で描く ―
  クラゲの触手を細い線で描いていた頃は、影絵ではただのドームだった

## 戦いの手触り(この回で明示的に頼まれた変更)

戦闘の数値は勝手に触らないという原則の例外。いずれも言われた通りの挙動変更:

- **大きさの段階は時計にする**: 危険度(遠さ)で大型が増えると、遠い土地はどこも
  巨体で埋まって同じ絵になる。遠さは色違いと敵の顔ぶれで語り、体の大きさは
  終焉の刻(30分)へ向かう時計にした。実測の大型比率: 序盤2.0% / 中盤9.6% / 終盤54.5%、
  同じ時刻なら遠くでも近くでも変わらない(1.9% と 2.0%)
- **敵の気づく距離をこちらの射程と連動**: 固定の75〜115pxのままだと、射程を伸ばすほど
  「撃たれているのに寄って来ない案山子」が増える。`max(その個体のaggro, 主人公の射程)` に。
  素の射程68pxはアグロより短いので、初期の間合いは変わらない
- **仲間が身代わりになる**: 敵と主人公を結ぶ線の上、敵の腕の届く所に立っている仲間が
  いれば、その一体が受ける(全方位の無敵にはしない)。軍勢に囲まれているのに
  主人公だけ殴られ続けるのでは、仲間を連れている意味がない
- **仲間の当たり判定に大きさを反映**: 接触ダメージだけ `a.def.r` を素で使っていて、
  大型を仲間にしても細い体のまま判定していた(飛び道具の判定は元から大きさ込み)
- **攻撃力の下限をHPの1/10に**: 硬いだけで何も削れない個体は、敵としても脅威にならず、
  仲間にしても頭数が増えるだけ。敵・仲間の両方に同じ床を敷く(定義上1/10未満の8種が対象)
- **カリスマ(仲間になる確率)を+0.2%→+1%/Lv**に

## 遊びの筋を通す(この回の直し)

- **宝箱の音**: 買い物音(角の立つ矩形波)の流用に加え、飛び出すコイン5〜8枚が
  それぞれ鳴って一箱でうるさく重なっていた。柔らかい三角波の専用音にし、
  噴き出したコインの音は1.2秒鳴らさない
- **誰に殴られたか**: 方向のフラッシュだけでは混戦でどの一体か分からない。
  殴ってきた相手に赤い輪・主人公との線・名札を1.1秒出す
- **街ですり抜ける**: 押し出しが1回だけだったため、押し出した先がもう一つの壁の中に
  なる角や路地で、壁を抜けて建物に入れた。どこにも食い込まなくなるまで繰り返す
- **街の建物の重なり**: 港町の町家を108px間隔・高さ最大150pxで並べていたため、
  全8港で必ず重なっていた(実測34件)。高さを先に決めて帯の中に割りつけ、
  路地幅40pxを必ず空け、荷揚げ場の前には建てない。実測0件
- **船に乗った直後に陸へ戻る**: 乗船地点は渚のすぐ沖なので、一歩動くと自動上陸していた。
  出航から2.2秒は上陸せず、岸に沿って滑る
- **しに戻り後のスキル取得**: スキルと素材は周回ごとに白紙に戻るのに、広場でも取得できた
  (しかも余り素材は既にコインへ換金済み)。旅の外では取得を閉じ、理由を画面に書く
- **スキルの並び**: 定義順のままだったので、補助と仲間と心得が入り混じっていた。
  種類ごと・軽い順に並べる(未見→取得可能→それ以外 の三段は据え置き)
- **「全ダメージ」の表記**: 実際は主人公の攻撃だけ(仲間は allyAtk が別枠)。
  12件を「主人公の与ダメージ」に改めた
- **Lv1の効果が読めない**: 30件のスキルが「〜が上がる」としか書いておらず、
  取っても何も起きないように見えた(ウォーバナーはLv1で既に仲間攻撃+20%)。
  全て数字で書く
- 検証: battle.js(大きさの出方 / 攻撃力の床 / アグロと射程 / 身代わり / 出航直後)、
  overlap.js(全37マップの建物の重なり)、nopass.js(全建物へ16方向から押し込んですり抜け検査)

## バイオドームの行商人(そこで採れない素材を担ぐ)

- 各バイオドームに街道の行商人が立つ(約12チャンクに1人、陸の上、港・基地・出発点から離れて)。
  扱うのは `DATA.BIOME_WANTS` ― **そのバイオドームでも、BIO_ORDERで隣り合う
  バイオドームでも採れない素材**だけ。一歩隣で拾えるものは扱わないので、歩く代わりにはならない
- 表は敵のドロップ表と地形物から機械的に作る(敵や素材を足しても表がずれない)。
  木・岩・木箱から出る素材(木材・鉄クズ・水晶・魔石・ゼリー・獣の毛皮)は全ドーム共通で「採れる」
- 虹のかけら(レアモンスターの落とし物)だけは売らない ― 店で買えるなら探し当てた値打ちが消える
- 一人がそのドームの不足分を全て担ぐ。分担にすると陸の少ないドームで
  誰にも当たらない素材が生まれる(それは調整ではなく足止めになる)。品数が多い時は
  「別の荷を見る」で見せ切る
- **どのバイオドームにも必ず一人は立つ**: 確率だけに任せると、陸の狭いドームで
  たまたま誰も居ない土地が生まれる(実測で20ドームに1回ほど)。ドームの中で
  立てるチャンクのうち、決まった順で最初のものを「必ず居る一人」にする
  (ドームは約8チャンク四方なので±10チャンク見れば同じ答えになる。ドームごとに一度だけ計算)
- 値は素材の階級で決まる(🪙60×(tier+1)で5個)
- 検証: peddler.js(24ドームを抜き取り、そのドームの不足素材を全て買えるか /
  隣のドームで採れる品を売っていないか)
